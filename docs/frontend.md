## 7. 前端设计要点

### 7.1 波形与播放（性能生死线）

12 小时音频的坑：

- `decodeAudioData` 整段解码 = 12h × 16k × 2ch × 4B ≈ 5.5GB 内存 → **必崩**。
- 所以：**wavesurfer v7 + MediaElement 后端**（`<audio>` + `<audio>` 直接流式），峰值用后端预计算。

峰值文件格式（`peaks/<sha256>.pkc`）：

```
header: magic 'PKC1' | version | sample_rate | channels | duration_ms | levels
level k: buckets_per_second (8, 64, 512, 4096)
         每 bucket 存 (min_i16, max_i16) × channels
```

- 后端：`ffmpeg -i in -f s16le -ac N -` 流式读 → numpy 分块 → 逐级降采样，内存 O(block)。
- 前端按缩放级别选择 level，一次只取可视窗口 ± 2 屏的 bucket。**不要一次加载全文件**。
- 10h 音频按 512 buckets/s 约 1840 万 bucket，单 level 约 74MB → 必须分块 HTTP Range 拉取。

**缩放只能从两个入口改变：波形上的滚轮，和下方的 − / + / 全部 三个按钮。**
这条不是洁癖，是修过的 bug：自绘滚动条上曾经挂着 `onDoubleClick` 回到全览，
而「连点进度条」的第二下正好落在下面那条滚动条上，于是一次误点就把花了很久
调出来的缩放窗口扔了。缩放是用户一次设定、期望一直保持的状态，
所以重置必须是一个**不可能误触**的目标：「全部」按钮，而不是双击某个热区。

同理，画布上的 `+` / `-` / `0` 键也拿掉了：画布默认是 `tabIndex=0`，聚焦后
一个误按的数字键就能把窗口改掉，而它离鼠标正在操作的地方很远。
保留的只有定位类键：`Home` / `End` 平移到两端（不改跨度）。

**滚动条只做平移。** 拖滑块、点轨道空白处都只改 `from`，不改 `to - from`。
一个控件只干一件事，才不会在「我只想往右看一点」时把跨度也改了。

**句尾手柄在最后一句、而且是文件最后一句时，只有「往后拖」是有用的方向。**
这里曾经有个 bug：`adjust_token_edge` 的 `end` 分支在缺后邻时把上界设成了 `token.end_ms`
自身，于是**只有最后一句的句尾**拖不动——而且提示语说「不能晚于 3693570ms（会与相邻字
重叠）」，把原因归给了并不存在的相邻字。句首一切正常，所以看起来像「只有句尾坏了」。
句尾被切掉半个字正是最需要往后拖的场景。现在上界改为文件时长（`version.duration_ms`），
越界时理由改成「不能晚于文件结尾」。

**复现这种 bug 的走查不能靠猜像素。** 波形滚轮缩放的锚点是鼠标位置，窗口还会跟着播放
位置移动，而画布只暴露跨度、不暴露 `from`——纯算术推出来的手柄位置会把测试引到别的句子上
（我在这上面连续错了五版，抓到的是 6536、8134 这些不相干的 token）。可靠的做法是：点到
最后一句让窗口跟过去，然后**从右往左**扫 `canvas.style.cursor`，第一个 `ew-resize` 就是
最靠右的手柄，再用请求体里的 `token_index` 核对确实是 8234。

**命中判定必须承认「瞄不准」。** 上面那句「扫 cursor 找手柄」之所以一直有效，是因为
旧规则是「6px 内最近的手柄」。但手柄密度会随集数增长：61 分钟、1682 句 → 3364 条边界
铺在 978px 上，平均 **0.29px 一条**。于是画布上**每一个像素**都落在某个手柄的 6px
半径内，`handleAt` 永远返回手柄，点击全被拖拽分支吃掉——按住松手没动就什么都不发生。
实测：横向六个位置各点一次，时钟一次都没动；而同一条水平线上点顶部字幕条（另一条
代码路径）立刻跳到 38:08。

现在 `hitEdge(xs, px, hitPx)` 要求「最近的那条在半径内，**且**下一条不同的边在半径外」。
两条边落在同一像素时算同一条边（句尾和下一句句首本来就重合），既不误判也不漏判。
拥挤时返回「没有手柄」，点击落回去当 seek——那正是用户的本意。放大之后手柄分开了，
拖拽自动恢复，正好也是「拖得动」的那个条件。

**「同一条边」要按位置比，不能按距离比。** 第一版比较的是距离排名（第一名和第二名
差多少），而两条相距 4px 的手柄在中点上距离相同，排名差为 0，会被当成同一条边放行。
改成拿最近那条的**坐标**去和其他边比，只在坐标重合时才视为一条。

### 7.2 校正台布局

```
┌───────────────────────────────────────────────────────────────────────┐
│ 顶部：项目名 · 版本号                          （项目名 · v3）        │
├─────────────────────┬─────────────────────────────────────────────────┤
│ 热词   本次带入31个 [收起] │ 视频剪辑  模板已套用·2块           [展开] │
│ ┌ 本期29 全局2 ───────┐ │ ┌── 预览 ──┐ ┌ 模板|字幕|素材库|演示稿 ┐ │
│ │ [chip][chip][chip]  │ │ │  16:9    │ │  （选中的那一页设置）    │ │
│ │ 添加本期热词…        │ │ └──────────┘ └────────────────────────┘ │
│ └─────────────────────┘ │ 视频轴（与下方波形同一个窗口）             │
│ 字幕        [另起一句][并入上句][并入下句][合并句子]                 │

│  └                                                        │          │
│ 操作记录                    [刷新] [收起]                  │ 音频剪辑  成片61:36 [收起]│
│                                                            │ 00:00.000 583句 · 8180词│
│                                                            │ ┌──── 波形 ─────┐      │
│                                                            │ [▶][⟨][⟩] [删除选中][导出]│
└─────────────────────┴─────────────────────────────────────────────────┘
         左栏 420px                        舞台区（占满剩余）
```

**三段是同一张卡片，不是「两个卡片 + 一片空白」。** 字幕区原来没有外边框、没有圆角、
背景是侧栏底色——它读起来像「内容漏到了布局外面」，而不是第三段。旁边两个是有边框的卡片，
唯一没有框的那个反而是整天盯着看的那个，这个反差本身就是错的。

现在三段共用 `.panel` 的那套外观（1px 边框、8px 圆角、`--surface` 底），字幕区靠
`.transcript-pane` 自己套一份而不是复用 `.panel` 类，因为它的 `flex: 1` 和内层滚动结构
跟卡片不一样。量出来的三项已经一致：

| | 边框 | 圆角 | 标题左缩进 | 标题字重 |
|---|---|---|---|---|
| 热词 | 1px `--border` | 8px | 11px | 600 / 12.3px |
| 字幕 | 1px `--border` | 8px | 11px | 600 / 12.3px |
| 操作记录 | 1px `--border` | 8px | 11px | 600 / 12.3px |

**标题下面那条分隔线去掉了。** 另外两个面板的标题下面都没有线，唯独字幕有一条——正是
这条线让它看着像「一个工具栏焊在一个盒子上」，而不是盒子自己的标题。边框已经交代了边界，
再加一条线是重复计费。

**内边距搬到 rail 和行上，不留在容器里。** 列表必须贴到面板边缘，滚动条才会紧挨着右边框，
行的 hover / 选中背景也才能铺满整宽。容器留 padding 会把这两件事一起做坏。

**左栏是三段，中间那段才是要干的活。** 热词是参考材料（配好就不用再看），操作记录是事后核对（想起来才看），只有字幕是全程盯着改的。所以上下两段可以收起，中间不设收起。

**收起 = 标题行 + 「展开」，不是隐藏。** 面板整个消失等于把「这儿原来有什么」和「怎么弄回来」一起藏掉，用户只能靠猜。标题行里保留摘要（「本次会带入 31 个热词（全局 2 · 本期 29）」），是因为它回答了「要不要打开看一眼」——这正是收起状态下唯一还需要知道的事。收起后 `.collapsible-panel` 不再占 `flex` 高度和 `26vh`，空出来的空间全部给字幕区（实测两个都收起时句列表 280px → 703px）。

**收起状态不持久化。** 刷新后回到设计好的布局，是不需要写文档说明的行为；记住上一次的折叠会让下一次启动看起来"坏了"，而用户不会想到是九个小时前自己点的。

**「字幕」这一行既是标题也是工具栏。** 原来这里写的是「句边界」——那是个**按钮组的标签**，读起来却像"这一整栏都是关于边界的"，而边界只是这儿能做的四件事之一。改成「字幕」：标题说这一栏**是什么**，右边四个按钮说能**对它做什么**。样式与另两个面板标题**逐项相同**（同字号、同字重、同灰色）——最初写成粗体+前景色，结果它的视觉重量压过旁边两个，看起来像两种级别的标题，而它们其实是并列的第三块。按钮组 `margin-left: auto` 靠右，而不是给整行 `justify-content: space-between`——后者在一行放不下、换到第二行时会把按钮拉开，看着像两排互不相干的东西。

**为什么句边界按钮搬进文字区**：它们的操作对象是"这段文字"，摆在舞台区的底栏里时，用户的视线要在两个区域之间来回跳。搬到句列表上方后，按钮、选区摘要和它作用的文字在同一列里。

**每行的 ▶ 旁边必须有 ⏸。** 运输栏在窗口最右边，而你在读的是左边这一列——听到不该听的
地方想停，手要横穿整个屏幕。所以每行给一对：▶ 从这句开始播，⏸ 当场停。⏸ 停的是**播放器**，
不是"这一句"：音频只有一个播放头，假装按句停就是撒谎；它的 `disabled` 由全局 `playing` 决定，
没在播时灰掉（opacity 0.35 而不是 0，因为"它在那儿但不能按"和"它不见了"是两回事）。

**正文密度：0.9rem / 行高 1.5（原来是 1.05rem / 2）。** 1440×900、两个侧栏面板收起时，
一屏从 **5.9 句** 涨到 **8.1 句**，单行正文高度从 128px 降到 63px。行高 2 是给"选中气泡贴在
词下方"留的位置，但那只是一次一个气泡，不需要整整一行的空白。0.9rem 是下限：点选单位是整个词，
中文字再小就分不清 日/目、末/未。

**整栏还能像抽屉一样整体收起。** 三个面板各自能折，但它们加起来是**一个工作区**，共用一条右边框；当你要做的是「看视频版面」「导出」「调设置」时，需要的不是折掉某一段，而是让整栏让位。所以 `.sidebar` 的右边框上挂了一个 14×64 的把手（`.drawer-handle`，`‹` / `›`），点一下整栏收到 0 宽，把手跟着移到窗口左缘。

把手必须**画在边框上**，不能放进菜单：它折掉的就是它贴着的那一列，放在菜单里等于让用户先去别处找「怎么关掉左边」，而且关掉之后屏幕上没有任何东西提示怎么打开。抽屉关着时把手仍然可见，正是这个道理。

两处数字是从走查里量出来才定下来的：关着时把手 `left` 不能是 `0`——居中在 14px 宽的元素上会有一半跑到屏幕外（实测 `left: -7`），可点面积只剩 7px，所以停在 `7px`；侧栏的 `visibility: hidden` 是必要的，只把 `grid-template-columns` 设成 `0` 时，flex 子项仍按 min-content 撑开，栏根本合不上（实测宽度 420 → 0 需要这一条）。

**不再给字幕区加「收起」**：热词和操作记录是材料，字幕是工作本身。收起它等于把整个编辑面折掉——没有第二种用法成立，所以按钮本身就是噪音。至于「整栏收起」，那已经由抽屉把手负责，不重复。

**为什么不再有"改文字"输入框**：表单是第二个需要维护的状态（打开、取消、当前目标），并且和选区状态容易不同步（旧实现里按钮曾把 `undefined` 当提案发出去）。改成贴着选区的气泡后，"选中 → 点"是同一个动作的延续。

### 7.3 词级选择交互

- 句内每个 token 渲染为一个可点格子（不是 contenteditable）。**这是为了能用区间运算，而不是依赖 DOM 选区。**
- 点击 = 选中**整词**；Shift+点击 = 连选到该词；拖拽划过 = 按词范围选（不会选到半个词）。
- 选中态 = `{from, to}` 的 token 半开区间，句选与词选互斥（一次只有一个明确目标）。
- 选中后浮出气泡，三个按钮。**首尾两个是方向相反的成对按钮**，中间是修正：

  | 按钮 | 快捷键 | 作用 |
  |---|---|---|
  | **删** / **还** | `Del` | 未删除时是「删除」（红）；已删除时变「还原」（绿），把音频拿回来 |
  | **修** | `Enter` | 「修正」这个词而时间不变；**多词选中时合并成一个词** |
  | **隐** / **显** | `Backspace` | 只在字幕中「隐去」这些词而音频不变；已隐去时变「显」放回来 |

  按钮只写一个字（删 / 修 / 隐 / 还 / 显）。带图标的两个汉字（「✂ 删除」）在气泡的固定宽度里
  会折成两行，整个控件看起来像坏了；单字在任何缩放下都是一行，含义放在 `title` 里——悬停即见，
  而且平时不占地方。为了无障碍，`aria-label` 仍是完整的两个字。

  **「还」用绿色，和红色的「删」区分开。** 两个按钮占同一个位置（一个词要么被删要么没有），
  所以颜色说的是「这个按钮往哪个方向走」，不是「这是两个按钮里的哪一个」。
  还原如果也是红的，看起来就像又一次删除。

  **删 与 隐 互斥，UI 必须自己说出来。** 一个词的音频要么被剪掉、要么还在；
  对着一个已经删除的词点「隐」，会造出一个下面没有音频的隐去词，而对着已隐去的词点「删」，
  剪的是用户刚刚明确决定要保留的声音。所以：

  - 选区**全部**已删除 → 首按钮变「还」并转绿；
  - 选区里**有任何**一个词已删除 → 「隐」禁用，`title` 说明原因（"先用「还」还原"）；
  - 选区里**有任何**一个词已隐去 → 「删」禁用，`title` 说"音频本来就没删，先用「显」放回字幕"；
  - 全选已隐去 → 「隐」变「显」，仍可点（恢复）。

  「全部」决定**标签**，「任意」决定**能不能点**：只要选区里有一个词处于另一个状态，
  那个动作对整段就已经是假话了。快捷键与按钮完全一致（`Del` 在已删除的选区上是还原，
  `Backspace` 在已删除的选区上什么都不做），否则肌肉记忆会走到一条按钮不允许的路上。

  多词修正不再被禁用：它要解决的正是"拖过四个字、写成一个正确的词"。合并后
  首末两端的时间点保持原样，中间的边界消失在那个词里——这比"改不了"更符合直觉，
  也比"逐个改"少按三次。
- 快捷键只在**有词选**时生效，且输入框聚焦时不抢键（Backspace 在输入框里是删字符）。
  删除与隐去在语义上相邻、在危险程度上相差一档，所以按键也相邻：Backspace 是
  轻的那个。
- 词的状态用颜色说话，且**落库**（不是会话态）：
  - 已删除 = 红字 + 删除线 + 淡红底；
  - 部分删除（边界拖动啃掉词的一边）= 红字 + 点线删除线（不能声称整词都没了）；
  - 已修正 = 蓝字 + 淡蓝底 + 下方蓝线 + 角标 ✎；
  - 已隐去 = 灰字 + **点线**删除线 + 角标 ◌。用点线而不是实线，是因为实线的
    删除线已经在说"这段音频没了"，而隐去恰恰相反。
  - 句首的 meta 区会汇总：「已隐去 N」。
- **隐去的词在波形上是一块灰色斜线区域。** 左右两条边线 + 浅灰底 + 45° 斜线，
  区域覆盖整个画布高度（字幕带也算），所以“从哪到哪”一目了然。
  早期版本只在起点画一条竖线，回答了“这里有事”但回答不了“到哪里结束”——
  用户只能猜。

  **必须和删除分得开**：删除是实心红块、没有任何纹样，因为音频真的没了；
  隐去是浅色洗淡 + 斜线，斜线读作“从文字里划掉”，而下面的波形仍然透得出来。
  斜线间距 6px：一段隐去往往只有两三个词（常规缩放下 10–30px 宽），
  间距太大会有区域一条斜线都没捕到，看起来就像纯灰块——也就像删除了。
  连续隐去的词合并成一个区域（按 token 流相邻判定，不是按时间相接——真实转写稿
  词与词之间有 100–200ms 静音，按时间判会裂成两块）。

- 空格键播放/暂停，`[` `]` 上一句/下一句，`Esc` 取消选择/关闭气泡。

**字幕区与时间轴互相对得上。** 两半屏幕说的是同一段音频，所以「我在哪儿」必须只有一个
答案。四个方向都做了，但**只有三个方向带跳转**：

| 手势 | 跳转 | 选中 |
|---|---|---|
| 勾句首方框 ☐ | 跳到该句**可听**起点 | 整句（原行为） |
| 点句中的一个词 | 跳到该词起点 | 该词（原行为） |
| 点时间轴 | 跳到该处 | **只高亮那个词**，不勾方框 |

- **跳转一律不缩放。** 缩放是用户一次设定、期望保持的状态（见 §7.1 的入口纪律），
  一个"定位"动作顺手改跨度，下一次点击就会落在别的地方。
- **句跳转用 `audibleStart`，不是 `start_ms`。** 句子开头的词被删掉后，它**听得见**的
  起点是第一个幸存词；seek 到原始 `start_ms` 会落在删掉的范围里，虽然 `seek` 会自己
  往前snap，但那要绕一趟，删得长时还会越过整个句子。
- **句跳转只在「加入选择」时发生。** Ctrl 取消勾选是撤回，不是定位；取消一个方框就把
  播放头挪走是噪音。
- **点时间轴不勾方框。** 勾选意味着「删除选中」「并句」这些动作的对象变成**整句**，
  而用户点时间轴只是想看看"这里是哪儿"——把一次查看静默升级成整句操作是最坏的一种
  越权。句子的位置已经由播放头和 `.active` 底色说明了，信号够了。
- **点时间轴会清掉已勾的句子。** 这不是新规矩：词选和句选 everywhere 互斥，留着一个
  勾着的句子会让高亮显示一个词、而「删除选中」作用在整句上。
- **词是「有就选，没有就清空」，不找最近的。** 词与词之间有 100–200ms 静音，落在那里
  时诚实的答案是"这里没有词"。挑一个最近的词会把高亮指向没在播的音频，然后
  「删除选中」删的是用户没指过的东西。
- **查找用 `seek` 的返回值，不用点击位置。** `seek` 会从删除区间里往前snap；按点击位置
  查会高亮被删掉的那些词，而不是真正在播的声音。

**从时间轴选中的词要滚进视野。** 它可能在几千行之外，光高亮是看不见的。但已经在本屏的
词**不能**滚——点词本身就在改选区，每次都滚会把它从指针底下移走。所以判断的是
`rowVisible()`，而不是「反正滚一下居中吧」；比视口还高的行（这个栏宽下很常见）反过来
判「是不是已经铺满屏幕」，否则它永远不算"完整可见"，每点一个词都滚一次。

**但这个「滚过去」只能由选区变化触发，不能由重渲染触发。** 第一版把它写成

```ts
const range = selectionRange(selection);      // 每次渲染新建对象
useEffect(() => { if (!rowVisible(...)) revealOrd(...) }, [range, ...]);
```

`range` 的引用每次渲染都变，于是滚动引起的重渲染（`onScroll` → `setScrollTop`）
也会唤醒它；它重新发现选中的词不在屏上，就滚回去。用户看到的是：点完时间轴，
字幕区被锁在那句话上，滚一下就自己弹回来。

教训不在 `useMemo`，而在**判据放错了层**。这个 effect 想说的是「**选区变了**时把它带进
视野」——那是依赖层面的信息，必须落在 dep 数组里。写成「每次渲染都跑，再用
`rowVisible` 猜是不是用户自己滚走了」是不行的：走到那一行时，「用户刚滚走」和
「选区刚移过来」的状态完全一样，`rowVisible` 分不开。

实测（`scripts/check-scroll-lock.mjs`，真实滚轮事件）：

| | 点时间轴后 | 再滚四下 |
|---|---|---|
| 修之前 | 33303 | 32646 → **32646 → 32646 → 32646** |
| 修之后 | 34570 | 34810 → 35050 → 35290 → 35530 |

修之前那 657px 的回弹就是它：滚轮推到 32886，effect 拉回居中位置 32646。注意
「四步全都不等于基准值」——只比较「和初始值不同」的检查会判成正常，所以检查必须看
**相邻两步**有没有真正前进。

**播放要能自己从「解不了码」的位置里爬出来。** 真实事故：点 03:35.180 那句的 ▶，
传输栏变成「暂停」却一点声音都没有，也没有任何提示。根因是三件事叠在一起：

1. Chrome 的 MP3 解码器在这个位置有一个约 30ms 的坏窗口（215.14s 和 215.20s 都能解，
   215.16–215.19s 报 `MEDIA_ERR_DECODE`）。文件本身是好的：`ffmpeg` 全片 153,998 帧
   零错误，重新封装也不改变坏窗口的位置——是浏览器对某一段 granule 挑剔。
2. 元素一旦进入 error 状态就**不会**自己恢复：把 `currentTime` 挪到别处完全无声无息，
   `load()` 回原位仍然失败。只有 `load()` + **换一个位置**才行。这是实测的，不是猜的。
3. `void audio.play()` 把 reject 吞掉了，所以失败是**看不见的**。

修法：所有播放入口（`play` / `playRange`）都走同一个 `startAt()`，它按 30 / 60 / 120 /
240 / 400ms 的阶梯重试，每次都先 `load()` 再定位（顺序不能反）。成功后在提示条上写
「这个位置开头的几十毫秒无法解码，已跳过。」——**绝不静默挪时间点**。阶梯走完还不行
才报错，并说明换一句或导出后试听。

400ms 是上限：再往后就开始吃掉用户想听的那个字了，而「播放这一句」悄悄吞掉开头
比直接说播不了更糟。

判定「是不是解码失败」不能看 `play()` 的 reject——坏位下这个 promise **永远不 settle**
（实测 4.5s 既没 resolve 也没 reject）。所以 `attemptPlay()` 把 promise 和元素的
`error` 事件、600ms 计时器一起 race，然后读 `audio.error.code`。

**选中时版面必须不动。** 选中态只在词上换颜色和浮出气泡，**不能在工具栏里加一行说明**。
早期「句边界」rail 末尾有一行「已选 N 个词「…」」，词一长就换行、面板高度跟着跳，
用户点到哪面板长到哪——比不给提示更难受。同理 rail 里那条「并入上句会跨说话人」
的告警虽然只在冲突时出现，但它占满一整行（`flex-basis:100%`），所以现在**行始终预留**
（`min-height:1.4em`，无内容时渲染空串）：文字照旧出现和消失，几何不变。

**气泡要跟着它的词走，而词会跟着列表走。** 气泡位置是**屏幕坐标**，点击那一刻量一次；
但这个列表会自己动——点词会 seek，播放头跨句，跟随效果滚动。实测
`scripts/check-bubble-anchor.mjs`：滚动 23px 后气泡偏离词 26px，滚动 121px 后偏离
**104px**，长得能压到下面的「操作记录」面板上，看起来像在给那一栏做操作。

修法是在 layout 阶段重测 `[data-token]` 的矩形并更新锚点，而不是算「列表滚了多少、
气泡也挪多少」：行可能被重新折行、被虚拟窗口卸载再挂载、或者整栏宽度变了，
只有元素自己知道它在哪。词没挂载时什么都不做——那时气泡本来就该藏起来。

**一个必须存在的限制**：词级意味着**改不了"半个词"**。想删掉"人工智能"里的"人工"，只能整词删除，或在波形上框选时间区间。

**替换长度不受限**：词级下一条边都是真观测，所以「人工智能 → AI」压缩 4 个 token 到 1 个 token 是合法的。UI 只在"新文本显著快于原音"时给一句提示，因为这种字幕读起来会别扭，但**不阻止**。

### 7.4 批量处理：删除与隐去

「处理」菜单是**所有批量操作的唯一入口**，每个条目直接打开已经限定好范围的动作：

| 条目 | 作用 | 会覆盖 |
|---|---|---|
| 删除口癖词… | 剪掉音频 | 口癖词 |
| 隐去口癖词… | 只从字幕/文稿去掉，音频不动 | 口癖词 |
| 删除静音… | 剪掉死气 | 静音 |
| 删除未转写语流… | 剪掉没有字的语音 | 未转写语流 |
| 删除全部三类… | 三类一次清掉 | 口癖 + 静音 + 漏字 |

**动作在菜单里选，弹窗不再提供模式切换。** 早期方案是一个「一键清理」加弹窗内的
删除/隐去切换，这是最典型的一种糟糕设计：同一个按钮根据一个用户忘了自己设过的开关
做两件截然不同的事（剪音频 vs 只改字）。现在打开弹窗时动作已经由菜单条目决定，
标题就写着它，不可能搞错。

**只有「删除口癖词」和「隐去口癖词」互斥**——一个词要么被剪掉，要么被隐去。静音和
未转写语流**没有对应的字**，隐去对它们没有意义，所以它们在「隐去口癖词」弹窗里
置灰并附上原因「没有对应的字，无法隐去」，而不是整行消失（消失了用户会以为菜单变了）。
其余三类操作互相之间不冲突，可以依次执行。

**还原是逐类别的**，并且口癖词拆成两条：

- 还原已删除口癖词（N）：把批量删除的口癖词音频拿回来；
- 还原已隐去口癖词（N）：把这些词放回字幕，**音频本来就没动**；
- 还原已删除静音 / 还原已删除未转写语流。

拆开是必须的：删除和隐去是两种行为，一个拿回音频、一个拿回文字。合成一条
「还原口癖词」会让用户不知道自己这一点会拿回什么——而且只能拿回一半。

**「还原已隐去」只认批量隐去的词**，手动按 Backspace 隐去的词不在其中。手动隐去是
用户逐字读出来的决定，一次批量还原把它抹掉就是覆盖用户的选择。实现上靠
	oken.hide_source（'' = 手动，'filler' = 批量），而不是把索引记在 edit_op 里
——后者在 token 重排之后会指向错的词。

**统计口径**：隐去不减少音频，所以弹窗底部写「本次会隐去 N 处 · 涉及 X 秒语音」，
而不是「减少」。删除模式仍然写「本次会删 N 处 · X」。隐去模式下三个阈值也收起并注明
不生效——它们只影响剪切。

**统计单位是「处」，不是「词」。** 相邻的口癖词（「嗯嗯」）在清单里是一行、在波形上
是一条灰带，所以这里说的 N 处就是 N 条灰带。183 个 token 会合并成 173 处，两处数字
不一致时用户看到的是「已隐去 173 处」紧接着「还原已隐去口癖词（183）」，那读起来就是
bug，哪怕两个数各自都对。服务端的 `hide_fillers` 和 `counts_by_kind` 都用同一个按
token 连续性分组的函数，测试里也钉住了这两个数必须相等。

**计划还没回来时不显示 0。** 首次打开要跑静音检测（3 小时素材要几秒到十几秒），
这段等待里如果显示「0 处」，用户读到的不是「未知」而是「没东西可做」，会直接关窗。

### 7.5 删除边界可视

- 词级删除：红块覆盖 token 的 `[start,end)`；
- 框选删除：自由 region，拖动边缘调整；
- 吸附到的静音谷位置画一条淡蓝色竖线，让用户知道"系统替你挪了 40ms"；
- **吸附只能向外**（起点只左移、终点只右移）。早期实现会让吸附把切点往里推，于是用户删到 6010ms、实际只删到 5991ms，有 19ms 他删掉的音频又回来了。

| 场景 | 指标 |
|---|---|
| 首次打开 3h 项目 | < 2s 可交互（波形局部先行渲染） |
| 10 万字句列表 | 虚拟滚动，滚动 60fps |

### 7.7 视频区与双时间轴

**舞台是两个平级面板：`视频剪辑` 在上、`音频剪辑` 在下**，chrome 完全一致——左边标题，
右边摘要加一个「收起 / 展开」。视频的那个默认收起，音频的默认展开。细节见
`docs/video.md` §19.3 / §19.7，这里只记界面约定。

**入口曾经是 `设置 → 显示视频区`，那是错的。** 一整个功能藏在菜单里，屏幕上没有任何地方
能看出它存在——要发现它只能去开菜单猜。改成面板之后，收起状态仍然占一行标题 + 摘要
（「模板已套用 · 2 个素材块」），既回答了「这个项目用不用视频」，又不需要先打开它。
菜单里那一项已删除；`CollapsiblePanel` 收编了视频区原来的自绘标题行。

**音频区的东西全部搬进了 `音频剪辑`：** 时间码行、波形、播放/上一句/下一句、删除选中/
恢复删除、试听成片。搬运时只改了两处 CSS：波形原来的 `margin-top: 12px` 是为了和舞台上的
信息行分开，进了面板之后它就变成标题行和波形之间多出来的空档，所以
`.audio-panel .waveform { margin-top: 0 }`。

**「导出」不再有按钮，只有菜单项（第 102 轮）。** 屏幕上原来有三处重复：视频面板底部的
`导出视频` 按钮、它旁边那行「成片 1 小时 1 分 / 原始 1 小时 1 分」、以及音频面板 transport
里的 `导出成片`。前两个去掉，第三个也去掉，全部收敛到 `导出` 菜单——那个菜单里本来就有
字幕 / Audacity 标签 / ShowNotes / 文稿 / 导出成片音频，交付物的出口只有一个地方。

那行时长是**第三份拷贝**：`音频剪辑` 面板自己的摘要就写着「成片 61:36 / 原始 61:36」，
而 transport 上面还有「583 句 · 8180 词 · 1 小时 1 分」。一屏三处同一个数字，删掉两处。

搬进菜单之后有两个必须一起做的改动，否则会静默错：

1. **字号 / 底部留白两个滑杆的状态提到 `App`。** 它们原来是 `VideoPanel` 的局部 state，
   因为导出按钮也在那儿。导出搬到 `App` 渲染的菜单里之后，滑杆的值只有面板知道——
   静帧预览会听话、成片会静默用回默认 52。所以 `VideoPanel` 改成受控组件
   （`fontSize / marginV / onFontSize / onMarginV`），初值仍从 `GET /video/subtitle-style` 取。
2. **成片导出完就保存，不留 URL。** 留 URL 就要回答「什么时候失效」，而它能在 EDL 不变的
   情况下失效（拖一个素材块会改画面但不改音频签名），菜单就会递给你一份和屏幕上的轴
   已经不一致的片子。一次性把这个问题取消掉，而不是回答得很差。

菜单项的可用性由一个纯函数算（`apps/web/src/videoExport.ts` 的 `videoExportEntry`），
不在 JSX 里写 `disabled={a || b || c}`：灰掉的菜单项看起来只有一种样子，但原因不止一种
（还没算完 EDL / 正在导出），说不清原因就是第 42 轮那个「点击后无反应」换了件衣服。
`npm test` 里有 9 条钉它。

**第 110 轮：「一次都没删」不再是其中一个原因。** 两个导出项原来都要求
`edl.deletions.length > 0`，理由是「视频用成片音频」——那是把 app 的管道倒过来当成了用户的
作业顺序。只做字幕校对然后直接出片是完全正常的用法，而它们在那种用法里全是灰的。
`videoExportEntry` 的入参里连 `deletionCount` 都删掉了：留着没人读的字段，下一个人加条件时
就会去读它。现在只剩两种情况会灰——EDL 还没算完（等待），或者正在导出（状态）。

**第 135 轮：两个导出项改成开面板，菜单里只剩「导出什么」。** 点「导出成片音频…」弹
`AudioExportDialog`，点「导出成片视频…」弹 `VideoExportDialog`。菜单从 9 项回到 7 项，四个配置项
（两个格式、两个视频开关）都收进了面板。

理由是菜单把两件事混在一起了：**「导出」是动作，「怎么导出」是参数**。原来 9 项里有 4 项是参数，
它们和动作并排、长得一样，却只有动作会产出文件。而且三个真正的需求菜单根本表达不了：
**起个文件名**、**选个文件夹**、**看进度**（进度挤在菜单项的 label 里，菜单一关就没了）。

| 面板 | 里面有什么 | 页脚 |
|---|---|---|
| `VideoExportDialog` | 文件名、导出到（可手填可「选择…」）、2 个勾选框、进度条 | 一个按钮：**导出 ⇄ 停止** |
| `AudioExportDialog` | 文件名 + 格式下拉（**同一行**）、导出到 | 一个按钮：导出 |

**没有「取消」按钮，关闭是标题栏的 ✕。** 视频面板里「取消」和「停止」并排时字面上分不清：一个
关面板、一个杀进程。而音频导出只要十几秒，连进度条都没有，更不需要「取消导出」这个动作。

**进度条只出现在视频面板**，因为它是十八分钟；音频是秒级。进度行 = `42%　约 10 分钟　<render.note>`，
`note` 仍然是服务端下发的「14 块串行编码：空闲 4.2 GB < 2 个并行需要的 8.3 GB」。

**四种终态用四种颜色，`cancelled` 是黄不是红。** 用户主动按的停止不该和编码失败一个颜色——
把两者画成一样，唯一的效果是训练用户忽略红色。判据在 `exportPanels.ts::progressView`。

**`done` 是两件事，面板必须分开说。** 服务端的 `done` 只表示**编码**结束；把成品拷到用户选的
文件夹是之后的一步，会失败、也要几百毫秒。所以 `ExportState` 里另有 `delivery`
（`idle` / `saving` / `saved` / `failed`）与 `savedTo`，`done` 那一支按它分三句：

| delivery | 进度行 | 色调 |
|---|---|---|
| `saving` | 编码完成，正在保存… | ok |
| `saved` | **已保存到 `<路径>`** | ok |
| `failed` | 编码完成，但保存到文件夹失败（见提示） | bad |

第一版没有这个字段，于是「正在保存…」在文件早已落盘之后仍然挂着——用户没法判断到底存成了没有。
**一句话如果不随事实改变，它比没有这句话更糟。** 保存失败也不能写成「导出失败」：编码确实成功了，
文件仍在数据目录里，说成失败会让人以为要重跑十八分钟。

**按钮的「在跑」和「有东西要显示」是两个概念。** 终态之后进度条**故意**留着（显示「已停止」），
如果拿 `job !== null` 当「在跑」，停止一次之后所有输入框就永久禁用了，用户只能关掉面板重开——
这是本轮走查抓到的真缺陷，现在拆成 `hasResult` 与 `isRunning`。

**第 132 轮那两个开销开关仍然存在，只是搬进了视频面板。** 它们都拿时间换用户自己拥有的东西，
所以文案必须让用户**看见自己换掉了什么**：

| 勾选项 | 设置项 | 换到的时间 | 换掉的东西 |
|---|---|---|---|
| 并行编码（需至少 8.3 G 内存） | `video_faster` | 2 个 ffmpeg 并行，实测 **1.09–1.23×** | 不够就还是 1 个，进度行写明原因 |
| 快速编码（文件更大） | `video_fast_encode` | 视频块 **−6.4 %** | 体积 **+8.2 %**，而且画面不再逐位相同（min PSNR 39.7 dB） |

三条实现上的理由，都不是风格问题：

1. **文案把代价写在括号里，不写成「优化」。** 「加速」两个字会让人以为免费；写「需至少 8.3 GB
   内存」之后，勾了没变快的人第一反应是看进度行的 `note`，而不是来问「为什么没用」。
2. **勾选 ≠ 生效。** 「并行编码」勾上只是**允许**开第二个进程，真正的判断在服务端（按当时的空闲
   内存和本片的块形状算）。所以那句理由必须回述：`render.note` 现在显示在**进度行**上。前端不知道
   内存，也不该知道。
3. **勾选状态是本机设置，不是项目设置。** 换机器、换空闲内存都会变，所以它存进 `settings`，
   和 `export_format` 一样是「这台机器怎么导」的口味，而不是「这一期怎么剪」的事实。存进项目会让
   一份 8 GB 内存机器上做的项目在 32 GB 机器上仍然保守地串行。面板里改完立刻 `saveSettings`。

**停止是真的停，不是打标记。** 点「停止」→ `POST /api/video/exports/{id}/cancel` → 编码线程在
**≤200 ms** 内 `kill()` 掉正在跑的 ffmpeg，终态写 `cancelled`。块之间打标记的做法会让「停止」
等一整个块（约 200 s）。技术细节见 [`docs/video.md`](video.md) §19.34.7，决策见 D24。

服务端契约在 [`docs/video.md`](video.md) §19.34.1（门限与理由）与 §19.34.5（编码参数），
`VideoExportOut.note` 就是那句理由的载体。

**视频面板内部是「预览左、设置右」，设置用标签页切。** 原来 模板 / 字幕 / 素材库 / 演示稿
四段是**竖着堆**的，堆完的结果是：要够到下面的视频轴，得先滚过四屏和自己当前目标无关的设置。
现在 `.video-stage` 是个两列网格——左边 16:9 预览，右边 320px 的设置卡片，
卡片顶部是四个 `.tab`（和 `ScriptPanel` 同一套样式），下面只渲染选中的那一页。

| 标签页 | 里面是什么 |
|---|---|
| 模板 | 素材框尺寸、4 个头像位的说话人绑定与亮灯时长、框内默认填充 |
| 字幕 | 字号 / 底部留白两个滑杆（原来挂在预览下面，现在归到「字幕」这个名义下） |
| 素材库 | `AssetLibrary`（导入、缩略图、拖拽源） |
| 演示稿 | `DeckPanel`（页列表 + 720×405 预览 + 标题/正文 + 两个字体下拉框） |

两处例外是量出来的，不是猜的：

- 「演示稿」那一页给设置列加到 **560px**（`.video-stage.wants-wide`）。它是唯一一个**双栏
  编辑器**而不是表单的页：320px 时页列表把每个标题截成六个字，等于把「逐页校对」变成
  「逐页猜」。
- 窄于 1180px 时两列**堆叠**。硬撑两列的话，设置列抢不到的宽度会让预览先塌掉，而预览才是
  这个面板存在的理由。

**视频轴挪到面板最后一行，紧挨着音频轴。** 这不只是排序偏好：两条轴画的是同一个时间轴，用户
要回答的问题是「这个素材块落在哪句话上」。块在预览下面、波形在另一个面板下面时，这个问题只能
靠对数字来答；现在把视频轴放在 `视频剪辑` 的最底、`音频剪辑` 的最顶，两条轴之间只隔 87px 的
面板边框和标题行，眼睛竖着扫一下就对齐了。视频轴下面是面板边界，再下面就是音频轴——轴是最后
一行，所以这一行**不再有按钮**（第 102 轮：导出收进了 `导出` 菜单，见上面那一段）。

**两条轴共用一个窗口，不是各算各的。** 这是本轮唯一改了数据流的地方。原来 `VideoPanel` 自己
持有一个 `{from: 0, to: 60_000}` 的窗口，而波形持有另一个（可以整段 61 分钟），于是「屏幕上同
一个横坐标」在两条轴上代表两个不同的时刻——素材块看着压在 12:00 上，波形说那里是 30:00。
`apps/web/src/timelineView.ts` 的 `useTimelineView` 把窗口提到 `App` 里，波形和视频轴都从它
渲染，缩放/平移/「跟着播放头」也都走它。

改成了受控组件的地方：`Waveform` 不再自己 `useState(view)`，改为接收 `view / total / onZoom /
onPan / onReset / onFollowPlayhead`；`VideoTrack` 接收 `view` 并新增 `onZoom / onPan`，滚轮
缩放与波形走同一个 `zoomAt`。`VideoTrack` 的滚轮监听必须是 **non-passive**——React 的合成
`onWheel` 不能 `preventDefault`，否则页面会在缩放时跟着滚。

对齐这件事还有个 7px 的坑：波形的 canvas 在 `.waveform` 里被 6px padding + 1px border 内缩了，
视频轴原本贴着面板内容边缘。实测 canvas `left 452 / width 956`，轨道 `left 445 / width 970`
——两条号称同一条时间轴的轨道起点差了 7px。`.video-track-wrap { padding: 0 7px }` 之后两者
逐像素相同（`452 / 956` 完全一致）。

走查里最强的断言是这条：在**同一条轴的同一个横向比例**上各点一次，读 `aria-valuenow`。
两次数值必须相等——各算各的窗口时它们会差出几分钟。实测 `trackTime 2734987 / waveTime 2734987`，
`deltaMs 0`。

**通知条留在舞台层，不放进任何一个面板。** 两个面板都会发通知（导入 PSD、绑说话人、导出）
——放进 `音频剪辑` 就意味着从视频面板发出的消息可能落在折叠区下面，等于没发。

**视频块不跟着删除变短跳变。** 这是最容易问错的一点：删一段音频，视频块在成片里是
**连续播放、总长变短**（内容循环/裁剪），不是中间被挖掉一块。所以：

- 素材块底部一条填充条表示成片占比（`keptPercent`），块上的第二行写 `起–止`（第 104 轮起；
  之前是单独的「原始 10.0s / 成片 8.0s」那一行，删掉是因为范围更常用，而占比已经有条了）。
- 成片长度来自 EDL 的实际 keeps 求和，**不是**锚点相减（吸附到静音 + guard 会差最多 20ms）。
- 画廊块按 B 语义缩放：显示 `8 张 · 每张 1.9s（原 2.2s）`。速度变化是可见的，
  否则用户会以为画面坏了。

**拖动吸附到句子起点。** 吸附半径默认 ±120 ms；`< 500 ms` 的相邻边界在 UI 上合并成一个
可落点（数据上仍各自有效）。首句之前和末句之后允许落到 `0` 和总时长。

**视频轴复用音频轴的手势。** 不重写时间轴组件：`waveView.ts` 的 `zoomAt` / `panTo` /
`msToX` / `xToMs` 是纯函数、已有单测托着，视频轴只换绘制和命中。两边现在不是「单向驱动」而是
**共用一个窗口**（`useTimelineView`）：在任意一条轴上滚轮缩放或拖滚动条，另一条立刻跟着变。
播放头仍然只有音频一个钟，两条轴都读它。

**默认收起。** 多数时候先剪音频，视频区占着高度纯属浪费。收起时是标题行 + 摘要
（「模板已套用 · 4 个素材块」/「未启用」），与热词、操作记录用的是同一个
`CollapsiblePanel`。「可整条隐藏」在改成面板之后取消了：收起已经够用，而「隐藏」会连
入口一起消失，正是上一版找不到功能的原因。

**有 plan 就是实时 DOM 舞台，没有 plan 才退回静帧。** 静帧由播放头停下 300 ms 自动触发，
不播视频；**播放中不请求**（一帧 ~0.7 s，排队只会交付没人看的结果）。这样「拖音频、拖视频块、
看预览」是同一个时钟，而不用维护第二套播放状态。

> **第 134 轮删掉了「生成静帧」按钮和它右边那行「输出时间 … · 实时预览（成片 1080p）」。**
> 按钮存在的理由是「DOM 舞台是预览，要能强求一张真帧核对细节」，但实测下来它只做到两件坏事：
> 有 plan 时花 0.65 s 换一张比舞台略差的图，没 plan 时自动出图本来就会跑。那行状态文字的一半
> （`输出时间`）与音频轴上的时间读数重复，另一半（「正在合成这一帧…」）已经有 `img.is-stale`
> 的变暗代替。**静帧路径本身没动**——它仍是拿不到 plan 时的唯一退路（§19.32）。

> **第 128 轮（P0）实测与改动**：这里原先写「实测约 200 ms」。在 3696 s 的样片上重量是
> **1020–1330 ms**，第 128 轮之后是 **634–929 ms（p50 ~730 ms）**，剩下的 88 % 是 ffmpeg 本身。
> 三件事值得在这里留一句：
>
> 1. **`at_ms` 是输出时间，播放头是原始时间。** 面板现在先经 `timeMap.ts` 映射再请求；
>    有删除的项目上两者差 `removed_ms`（实测 1.05–1.2 s），样片删 0 所以这个 bug 一直看不出来。
> 2. **请求带 `generation`**，过期响应直接丢弃；等待期间把上一帧降到 55 % 不透明度而不是清空
>    （`img.is-stale`），否则每次停播放头都闪一下空框。
> 3. **降分辨率救不了**（540p 只省 14 %）。真正的实时预览方案见
>    [`docs/video.md`](video.md) §19.31（服务端出 plan + 浏览器 6 层 DOM 合成，
>    4K 源实测 144 fps / 0 丢帧），决策 **D19**。

**演示稿面板是「左边原文、右边可编辑」。** 逐页校对的前提是能看见这一页覆盖了哪些字幕——否则
用户得凭记忆判断三分钟前说了什么。左列是页序 + 标题 + 时间点，右侧是 720×405 缩略图、版式下拉、
标题/正文两个输入框，以及「跳到这句字幕」「放进素材框」「上移/下移」「删掉这页」。它现在是
`视频剪辑` 里的**第四个标签页**，不再是一层 `<details>`：面板本身已经有一层收起，标签页又是
一层切换，再叠一个折叠头就有三个「点这儿能展开」的东西挨在一起。

**第 107 轮：两个动作从保存那一行挪到版式那一行。** 顺序现在是
`版式 / 上移 / 下移 / 跳到这句字幕 / 放进素材框 ……（右推）删掉这页`，下一行只剩保存。
分组依据是「说的是这一页的什么」：保存属于上面两个输入框，另外四个属于**这一页在成片里的
位置**。原来要找「放进素材框」得先扫过版式、上移、下移和一个破坏性按钮。

**第 100 轮之后，面板还要说清「这份稿是谁分的段」。** 页数旁边一个 4 字标签
（`按话题分段` / `按字幕停顿分页`），下面按需渲染 `warnings` 列表。理由：两条路径产出的页面
在结构上完全一样（一个标题、一段正文），肉眼分不出「模型找的话题」和「按停顿切开的字幕」，
而这正好是这一轮要修的东西——如果降级时不说，用户会以为功能没生效。`source` 和 `warnings`
是落库的（`deck.source` / `deck.warnings_json`），因为面板每次挂载都会重新 `GET`，只在生成
响应里给一次的话刷新就丢。

**空状态给两个按钮，不是一个。** 「按话题生成演示稿」会调一次模型；「按字幕分页（免费）」
带 tooltip 说清它免费、秒出、但翻页不看话题。原来只有一个「从字幕生成」，文案还写着「不花钱
也很快」——那正是这一轮要删掉的默认行为。

**正文那个输入框是多行的，要点一行一条。** 服务端把要点写成 `・要点` 换行连接（`PagePlan.body`），
渲染器逐行画；所以编辑框里看到的和幻灯片上看到的是同一个形状。渲染时加符号的做法会失效：
`body` 是用户可编辑字段，模型加的符号和用户改的正文会打架。

**缩略图和成片必须是两张图，不能共用缓存。** 编辑器按 720 宽预览、素材框按框的实际像素出图，
同一个页面在两个尺寸下渲染结果不同（字号是自动缩的，标题与正文的相对大小也跟着变）。第一版
按 `slide id` 缓存，先请求的那个尺寸会污染另一个——成片里正文变软并溢出框右缘。服务端现在把
尺寸写进文件名，前端只要把宽高带上即可。

**「放进素材框」传的是 deck id，不是 slide id。** 一个块覆盖一段时间，里面放哪几页由演示稿在
渲染时决定；这样用户重排页面之后，已经插进时间轴的块仍然正确。若改成固定某一页，重排后块就
指向了错误的内容。

**第 101 轮：工具栏下多一行两个字体下拉框（标题字体 / 正文字体）。** 三个决定：

- **整份稿一起换，不跟当前选中页走。** 字体是演示稿的属性，像 PPT 的母版；按页设的话用户点
  到哪页改哪页，成品会一页一个样子。所以它放在工具栏下面一行的位置，不在右侧编辑区里——右侧
  的字段全部是「这一页」的。
- **选项只来自 `GET /projects/{id}/deck/fonts`，不是模板页的 `/api/fonts`。** 那份列表包含纯西文
  和图标字体（模板的期号要用），而幻灯片每个字都是中文。实测这台机器 105 个族里只有 36 个能画
  中文，选错的后果是一页空框。
- **下拉框的第一个选项永远是当前字体，即使它不在列表里。** `<select>` 的 value 匹配不到任何
  option 时会渲染成空白，看起来像「没有字体」而不是「那个字体被删了」——deck 可能在别的机器上
  设过，也可能那个字由字体已经卸载。

改完要 `revision + 1` 让缩略图重新取一次：服务端换字体时会清掉 PNG，但 URL 里的 `width/height`
没变，不主动重取的话浏览器会一直显示旧字体那一张。

走查（`scripts/check-p4-deck.mjs`）断言的是**算出来的事实**而不是像素：列表里 60 条、
缩略图 `naturalWidth === 720`（404 和空白幻灯片在截图里长得一模一样）、点第三页后
`input.value` 与列表标题一致、原文面板 298 字。这三条正是「预览没加载」「编辑框没跟着换页」
「原文对不上」各自的症状。第 100 轮之后这些断言仍然成立——它们量的是面板，不是页的内容。
第 101 轮的走查换成了 `scripts/check-r101-fonts.mjs`：它把缩略图读进 canvas 分别数**标题区域**
和**正文区域**的差异像素，所以「标题换了字体、正文没变」是一个可断言的事实，而不是「看起来
对」。

**静帧是全尺寸的，不是缩略图。** 接口按模板的 `canvas_w/h`（这版 1920×1080）出图，界面只用
CSS 缩到框里——所以**像素位置和成片完全一致**，可以直接对着静帧量字幕有没有压到边。

**预览框只有 `aspect-ratio: 16/9 + width: 100%`，没有 `max-height`（第 104 轮）。** 原来那个
`max-height: 260px` 在 480px 宽的栏里看不出问题（16:9 正好 270），窗口一宽框高被截住，框里上下
留黑边、图又按 `contain` 缩进框里，两层留白。用户的原话是「居中铺满整个区域，随着宽度改变自适应
改变」——对视频来说，自适应就是高度跟着宽度，因为 16:9 是片子的形状（§19.1）。`object-fit:
contain` 保留：竖图不能被裁成 16:9。走查在 1440 和 1100 两个宽度各量一次（`480×270` /
`630×354`，图 = 框的内容区，去掉 1px 边框），只在 1440 量会漏掉「窄的时候碰巧对」的写法。
原先担心的「预览 540p、成片 1080p 所以字号有差别」在静帧这条路上不存在，文案因此写的是
「预览为近似：成片 1080p，字号与位置一致」而不是「会略有差别」。

**字号/留白两个滑块就在静帧下面，不在设置里。** 中间过程是「拖一下、看一眼」——放进设置对话框
的话要来回开关，而滑块每动一次就写一次数据库也说不通。所以滑块只改**本次预览和本次导出**的
参数，不落盘；要长期改，那是 `SubtitleStyle` 的默认值该管的事。

**视频块按原始宽度画，成片占比画成一条底边。** 用 `output_ms` 画宽度，两个共享边界的块会在
其中一个被剪过之后裂开一道缝，看起来像「这里没有视频」，其实它一直在播。所以宽度只来自
`duration_ms`，成片占比是块底部的一条填充条——「8.0s / 10.0s」这种数字很容易被跳过，一条条不会。

**落点按规则算，没有固定的默认长度。** 先吸附到句子起点，再跑到**下一个**边界；固定 5 秒对
任何素材都是错的（插话式的两句 3 秒，下一个话题 40 秒）。而且**绝不与已有块重叠**：重叠的块会
被框内链裁掉大半，看起来像「拖进去没反应」。落在已占用区间里就滑到那个块之后——那也是用户丢在
那里时想要的。

**拖动保持长度、只吸附起点。** 拖到两个边界之间就停在那里，**不**重吸附：把它吸回去等于把用户
刚拖到的偏移悄悄改掉。边缘手柄的命中半径是 8 **像素**而不是百分比，因为同一个块放大时 400 px、
缩小时 4 px。

**画廊加图用 `＋`，不用拖。** 时间轴的拖放目标是**时间位置**，落下去的意思是「在这建个新块」，
不是「加进这个块」。要表达后者的唯一无歧义方式是指名那个块。

**素材库是横向一条，不是侧栏。** 短促使用（导入、拖走、忘掉），常驻一列会去和字幕抢宽度。
文件被外部删掉时画成红框而不是隐藏——「文件没了」是导出失败前用户需要知道的信息。

**卡片 220px，`＋`/`✕` 竖排（第 104 轮）。** 卡片原来 148px、两个按钮并排，留给名字的位置只有
36px，「主持人与嘉宾合照.jpg」渲染成「主…」。用户这一轮的原话是「素材库导入以后需要显示原名，
而不是生成的随机字符串，否则难以区分素材」——名字存下了但读不出来，和显示哈希名是同一个问题。
走查因此断言 `scrollWidth <= clientWidth`，而不是「文本节点存在」：后者在截断时也成立。

**填充方式多了一个「模糊裁切」（第 109 轮）。** 五个选项的顺序是
`模糊填充 / 模糊裁切 / 完整显示 / 填满裁切 / 拉伸`——两个「模糊」相邻，因为它们共用同一条
背景链，区别只在前景：一个完整缩进框、一个按原像素摆放。列表在 `videoTimeline.ts` 的 `FITS`
里，气泡和模板页的「框内默认填充」共用同一份（两份拷贝会在某一次加策略时漂开，而漂开的表现是
下拉里有一个选项选了会 400）。

**素材块自己写名字和时间（第 104 轮）。** 块上两行：素材原名 / 演示稿标题、`00:00.000–01:10.970`。
原来这两样在面板里的一行「选中 01:10.970–03:18.850（127.9s）」里，只描述被选中的那一个块，而且
选中/取消会让下面的轴上下跳 40px。名字来自服务端 `video_item.label`（素材 `original_name` /
画廊「A 等 4 张」/ 演示稿「开场与节目定位 等 2 页」），前端只在 `label` 为空时退回
「素材 / 画廊 / 演示稿」。

**演示稿块的名字第 107 轮才真的变成「标题」。** 第 104 轮给的是 `deck.title`，而每份演示稿的
标题都是常量「演示稿」（`decks.DEFAULT_TITLE` 是唯一的写入口）——和前端给空 label 用的回退
文案一模一样，于是块上什么都没变。现在按**它播哪几页**命名，规则与渲染器同源（页占
`[start, next_start)`，块打开时在播的是最后一个 `start ≤ 起点` 的页）。多页读作
「第一页 等 N 页」，和画廊的「A 等 N 张」同一个句式。

**Shift+←/→ 只把这一边拉过去（第 108 轮）。** `Ctrl+←/→` 挪整块，长度不变；`Shift+←/→`
只动一边，长度改变。同一个 `neighbourOf`，相反的动词。两个键在键盘上相邻，因为
「把这块放这儿」和「让这块够到那儿」是同一个人相隔两秒会做的两件事。

只**变长**：邻居的定义就是完全在一侧，够到它永远是向外；一个时而不动、时而悄悄吃掉一截的
键，比一个时而没反应的键更糟。守卫只检查这一边**新覆盖**的区域——真实数据里有只重叠几毫秒
的块，按整段查会让这两个键在那些块上全死（第 107 轮的 `Ctrl+→` 也会一起死）。

**气泡里多了一个 M（第 108 轮）。** 素材自己的声音默认不进成片（`muted` 默认 `true`），
按钮因此初始是按下状态，文案说明「导出时生效」——预览是静帧，按下去当场不会有任何声音变化。
`aria-pressed` 必须等于 `muted`：这个按钮做的是**静音**，按下 = 静音；写成 `!muted` 会在
每个静音块上告诉读屏用户相反的事实。

**M 只在有声音的块上出现**（`has_audio`，服务端从 `video_asset.has_audio` 算）。永远灰着的
按钮等于在问「这块哪里坏了」，而答案是「没坏」。

**Ctrl+←/→ 把选中块贴到前一个 / 后一个素材上（第 107 轮）。** 拖动可以靠近但不能精确对齐：
吸附网格间距约 500 ms，手拖落在「差不多那里」，两个本该共享边界的块会差几百毫秒，而块之间
凭空多出一道缝，读起来就是「这一段没有视频」。规则在纯函数 `abutNeighbour`（长度不变、返回
`null` 表示不动），键盘监听在 `window` 上——轨道是 `role="presentation"` 的 div，给它
`tabIndex` 会在页面中间插一个 Tab 停靠点和 56px 的焦点框。所以必须挡输入框：`INPUT` /
`TEXTAREA` / `contenteditable` 里的 Ctrl+←/→ 是「按词移动光标」，留给它自己。

第三处是波形：`Waveform` 是可聚焦的 `role="slider"`，它的 `onKeyDown` 只认 `ArrowLeft` /
`ArrowRight`、不看修饰键，所以波形有焦点时按 Ctrl+→ 会**同时**把播放头推 `span/20` 并挪块——
一次按键两个编辑，而且播放头那一下会被随后的重新渲染盖掉，看不见。加了修饰键前缀的判断。

**第 108 轮把那行说明砍到只剩快捷键。** 原来它讲拖两端、拖块身、滚轮、Shift+滚轮——
全都能靠试出来，而且缩放手势和正下方那条波形**完全一样**：那半句是在给已经在那儿学会的人
解释音频编辑器。能试出来的不写，写不出来的是修饰键：屏幕上没有任何东西提示 Ctrl 和 Shift
存在。现在一行只讲这两个键做的事，以及「长度变不变」这个唯一不能靠试出来的区别。

**选中块上的气泡，不是面板里的一行。** 气泡里有且只有两样东西：填充下拉（`.video-bubble-fit`）和
「删除素材」。它挂在 `.video-track-wrap` 里、由 `has-bubble` 给 wrapper 预留 34px 一行，而不是
`position: absolute` 浮在轴上——实测浮着的时候，选中靠右的块会让气泡正好盖住设置栏的「框内默认
填充」。气泡自身的 `pointerdown` 必须 `stopPropagation()`，否则轴上那个「按下就是抓块」的处理器
会把块从菜单底下拖走。

**走查里 HTML5 拖放不能用鼠标事件驱动。** 真实拖拽会话是浏览器级特性，合成 `dragstart` 不会
创建它，drop 处理器永远不触发，走查就会得出「功能坏了」的结论而它根本没跑过。用 CDP 的
`Input.dispatchDragEvent`。

**头像位在「版式」详情里，一行一个。** 左边是 PSD 里的槽位名 + 名牌文字，中间是说话人下拉
（默认「不绑定（一直不变）」），右边是这一位**实际讲了多久**（`166 段 · 31 分 26 秒`）。

- **必须显示时长，不能只显示下拉框。** 绑到一个从没说过话的人身上时，渲染是完全正常的——那位
  永远暗着。没有 `0 段` 这个数字，用户看到的就是「绑了但没用」，而原因在字幕那边。
- **绑定是项目级的，时长是版本级的。** 一个项目一份模板，但可以有好几个转写版本；下拉框改的
  是前者，右边的数字按**当前版本**算。这也是 `PUT` 要带 `version_id` 的原因。
- **绑定单独请求，不塞进 `/video/template`。** 没模板的项目会 404，把它和模板放在同一个
  `Promise.all` 里会让模板自己的错误被覆盖掉，而那才是用户要先解决的那个。

### 7.7.1 DOM 实时预览（`<DomStage>`，第 129 轮）

视频区在**有 plan 时**改用 DOM 分层合成：`VideoPanel` 取 `GET /versions/{id}/video/plan`，
拿到就用 `<DomStage>` 画六层，取不到就退回原来的静帧按钮。两层是并存的，plan 是可选增强。

**图层顺序是量出来的**，不是猜的：`background → plate.png(底板) → overlay.png(描边) → box 内容
→ 头像 → text → 全屏(top) → 字幕`。注意**底板和描边都在素材框下面**（`build_filtergraph` 先铺
`layers` 再叠 `box`），和直觉相反；也正因为它们在下面，`kind="plate"` 的空档段什么都不用画。
这条顺序只写在 `videoPlan.ts::layersAt` 一处。

底板和描边**各带自己的 rect**（第 137 轮，§19.35）：底图是海报、底板是 1444×815、描边是
1456×829，三者不是同一张画布尺寸，所以前端不能用 `rect: canvas` 一把梭——只有 background 和
text 是画布尺寸。老 plan（后端给的 `plate_url` 为 null）就是「没有底板层」，描边按全画布画，
前端不需要额外判断。

**哪些段不画东西**：`kind="plate"` 和 `kind="transparent"` 不产生任何元素（底板在下面铺着）。

**只有两种 fit 需要烘图**：`blur_fill` / `blur_crop` 的**背景**要用 ffmpeg 的
`boxblur` + `eq=brightness` 烘一张，其余（`contain` / `cover` / `stretch` 的前景）都是原生 CSS。
`cover` 是左上锚定（`crop=W:H:0:0` ⇒ `object-position: left top`）；
`blur_crop` 的前景**不缩放**（`overlay=(W-w)/2:0`）。

**时钟**（最容易错的地方，两条都踩过）：

- 时刻先吸附到帧：舞台用 `frameStartMs(atMs)`，与静帧的 `frame_start_ms` 是同一个整数表达式；
- 片段内的偏移是 `frameStartMs(atMs − segment.start_ms)`，**不是** `atMs − segment.start_ms`；
- 循环片段再按 plan 下发的 `period_ms`（ffmpeg 的**流**时长，不是 `element.duration`）取模。

`<video>` 只在偏差 > 200 ms 时 seek；暂停时 seek 到精确值（`tolerance = 0`），
播放时按 `SEEK_TOLERANCE_MS` 容忍漂移。

**跨块切换：两个槽位，不是一个 key。** 媒体位置由 `mediaDeck.deckLayout` 算出两个槽，第 *k* 个
视频段固定住第 `k % 2` 个槽；播放头进入下一段前 **2.5 s** 就把它的 `src` 挂到另一个槽、暂停在
入点。于是跨块只是翻一次 `visibility`，不再「卸元素 → 挂新元素」——后者实测要 **116 ms** 才出第一帧
（≈2.8 个影片帧，那段时间盒子是空的）。卡槽必须画在 `layersAt` 给 media 的**那个位置**上：
每个图层都是绝对定位且没有 `z-index`，画在最前面会被背景盖住（一版就是这样，20 时刻全错、
位移却全 0）。

**时钟有两档，别合并。** `positionMs`（React state，`timeupdate` 驱动，Chrome 节流到 217 ms）
喂转写列表、波形、视频轨；舞台要的是 **50 ms** 粒度，走 `playheadClock` 这个外部 store
（`useSyncExternalStore`，只有 `LiveDomStage` 订阅）。把 `positionMs` 提到 20 Hz 会让整棵树
一秒重渲染 20 次：实测 rAF **49 → 27 fps**、跨块切换 **232 → 430 ms**。

**验收状态（2026-11-19，第 129 轮）**：已通过。真播放 12 s：**45.8 fps / 0 丢帧 / 推进比 0.995 /
跨块切换 75 ms（进 4K 段 189 ms）/ 图层粒度 p50 32 ms**；一致性 **20 个时刻 20/20**。
判据是「平坦区差 ≤ 2 % + 全局亚像素位移 ≤ 0.5 px」，不是 raw——理由见 [`docs/video.md`](video.md) §19.31.5。

**一致性检查里最容易被误判的一件事**：位移必须量到**亚像素**。1 190 970 ms 的真实偏移是
**+0.31 px**（变形像素素材 852×480 + SAR 640:639，Chrome 把 853.33 取整成 853，画 1439.44 px
而不是 1440），整数搜索只能在 0 和 1 之间选，选 1 就成了「差一像素」的假故障。
用相位相关 + 抛物线插值，判据 ≤ 0.5 px。

### 7.8 模板标签页：一列属性

`VideoPanel` 的「模板」标签页只有**一个**表单（`TemplateTexts`）：每行一个属性，共用同一个标签
样式。

几条不写在代码里就会踩的：

* **一次提交一个字段，在失焦时提交。** 每敲一个字都写服务器会让标题的每个字母变成一次请求。
  失焦（和回车）是设置项该有的手势。
* **`defaultValue` 只在挂载时seed 一次。** 提交后服务器返回的是**解析后**的文本；如果它和输入框里
  显示的不一样（清空某项会退回 PSD 的原文），输入框会继续显示旧字符串 —— 界面就和成片不一致了。
  所以 `key={text:${slot.text}}`：只有服务器文本变了才重挂，打字过程中不会丢。
* **字体下拉框的内容来自服务器**（`GET /api/fonts`），不是硬编码。硬编码会在没有字由的机器上
  提供「数黑」然后在渲染时报 503，而用户无法处理。`preferred` 是服务端**解析成功**的设计字体，
  所以它宁可空着也不会给出错的。
* **多行值必须用 `<textarea>`。** `<input type="text">` 的 value sanitization 会**删掉 CR/LF**：
  实测标题的 31 个字里有 `\n`，输入框读回来一个换行都没有。于是标题显示成一行跑下去，而且
  *任何*一次编辑（哪怕只改其中一个字）都会把剥掉换行的字符串提交回去，把设计的两行标题静默
  压成一行。期号按定义只有一行（`EP.23`），仍然用单行 input。
* **框内文字不显示也不可编辑**（第 99 轮）。它们是设计稿的占位符，素材一定会盖住；列出来再解释
  「这轮不参与渲染」只是占地方。

布局上，这一页的列比别的标签页宽：

| 标签页 | 设置列宽 | 原因 |
|---|---|---|
| 字幕 / 素材库 | 320 px | 滑杆和下拉框够用 |
| 模板 | **480 px**（`.wants-mid`） | 四列网格，字体名有 15 个字符 |
| 演示稿 | 560 px（`.wants-wide`） | 逐页编辑要同时看到列表和正文 |

实测：320 px 时字体下拉框只显示到「Alimama ShuH」，而这个标签页上唯一无法从画面推断的信息
就是「这块文字用了哪个字体」。网格是 `76 / 自适应 / 144 / 46`，家族名 144 px 刚好不再截断。

头像名的框只有 30×16 px，`彼方（嘉宾）` 塞进去会折成两行；所以期号和头像名是**单行向右长**
（`DrawSlot.wrap=false`），只有标题和其他文字在矩形内折行。

**第 98 轮补充（角色名 / 双色 / 未绑定即消失）**

* 表单一行的标签就是服务端的 `slot.label`：`期号` / `当期标题` / `主播1` / `主播2` / `嘉宾1` /
  `嘉宾2` / `页脚`。渲染 `<span>` 时不要再拼角色名 —— 「头像名」会让六行长得一样。
* 多段颜色的写法是 `EP.**23**`，输入框里显示的就是带标记的值。面板上有一句说明只在**确实有
  标记**时出现，否则每个项目都会看到一段用不上的教程。
* **未绑定的头像槽连名字一起消失。** 前端不要试图「补一个占位名」：画不画由绑定决定。
* 头像绑定行的小字读服务端**解析后**的名字。两处都按「主播先、嘉宾后、各自从上往下」排序，
  否则两列挨着却互相矛盾。

**第 99 轮补充（一个列表 / 名字来自绑定 / 说明全删）**

1. **头像行并进同一个表单，不再有第二个 `<ul>`。** 之前「主播1」在面板上出现两次：文字行里一个
   名字输入框、下面绑定行里一个标签。两处用了两种颜色（`var(--muted)` / `var(--text)`），读起来
   像两种不同的字段，其实是同一种。现在行序是
   `期号 / 当期标题 / 主播1 / 主播2 / 嘉宾1 / 嘉宾2 / 页脚`，全是 `.template-row` + `.template-row-label`。
2. **头像名输入框删掉，改成绑定 + 换图。** 名字由服务端从绑定推导（`video_avatars.name_plates`），
   换图按钮就在这一行的末尾。改绑定会**同时**刷新模板（`doBind` 里 `await load()`），因为名字牌
   是画面上的像素，不只是头像轨的状态。
3. **说明文字全部删掉。** 「两边不成对就按普通文字显示」「框内有 2 段模板文字…」「素材框 1440×810 ·
   4 个头像位」「PSD 里有 4 个隐藏的头像组」—— 四条都是真话，没有一条能指导操作，而且把用户要
   找的设置挤出了列。编译产出的 `notes` 现在只留**能修的问题**（缺标题层、素材框没底板），
   样例模板正常时是空的。多段颜色那行提示压到一句：「用 `**` 标出要变色的字，例如 `EP.**23**`。」

**第 111 轮：气泡里有两个下拉和两个字母。** 素材块的气泡现在从上到下是：块名 → 展现方式
（`素材框` / `全屏`）→ 填充方式（五种）→ **M / S** → `删除素材`。

两个下拉都**没有文字标签**。原来填充下拉前面有个「填充」，加上第四个控件之后气泡换行了；
而 `素材框` / `全屏` / `模糊填充` 这些词自己就说清了，标签只是重复。解释搬进 `title`，不打开
就一分钱不花——和第 99 轮「说明行只说快捷键」是同一条原则。走查脚本会断言
`select.closest("label").querySelector("span")` 为 `null`，防止哪天又长回去。

**M 和 S 是两个按钮、一个状态，而且恰好一个亮**（`docs/video.md` §19.24.1）。M 亮 = 这个块
静音，只有播客的声音（**默认**）；S 亮 = 它的声音顶替这一段的播客。「两个都不亮」不允许——那时
屏幕上两个暗字母，成片里这段的声音却仍然叠加着。

互斥由**服务端**保证（按 S 清 `muted`，按 M 清 `solo`，落到「都不亮」时回退 M），界面再补一刀：
按 S 时如果 S 本来亮着，发出去的是 `{solo:false, muted:true}`（回到默认），不是 `{solo:false}`。

**两个字母都是「目的地」，不是开关**：按 M 是「回到 M」，按 S 是「切到 S」，点已经亮的那个不发
请求也不弹通知。混音（素材叠在播客下面）因此从界面上消失——导出里那条路还在，只是没有按钮能走到
它。这是有意的：把「两个都暗」解释成混音，就是让一个视觉状态有两种说法，而这正是这一轮那个 bug
的形状。

没有声音的块两个按钮都不画（不是画灰）——理由同上：永远灰着的按钮会被读成「这个块怎么了」。

**第 116 轮：M 和 S 一起亮，是「高亮」反了而不是状态反了。** M 的高亮写的是
`muted ? "" : "is-on"`——第 108 轮只有 M 一个字母、语义是「按下 = 静音」时的双重否定，亮表示
「有声音」。第 111 轮加了 S 之后它就变成 bug：S 亮 → `muted=false` → M 也亮，同一颗气泡上同时
写着「静音」和「顶替」。`aria-pressed` 一直是对的，所以这是**读屏用户听到正确的状态、看屏幕的
人看到错误的状态**——只有目视走查能发现。修完高亮和 `aria-pressed` 读同一个字段；`check-r116.mjs`
两样都读并断言一致，这条断言是这一轮唯一不会随时间失效的防线。

**第 115 轮：全屏块在屏幕上「盖住一切」，这一点在气泡里看不出来。** 气泡只提供两个词
（`素材框` / `全屏`），但两者的差别不只是大小：全屏块画在头像和文字**之上**，框内块画在它们
之下（`docs/video.md` §19.26）。所以同一张图从「素材框」改到「全屏」，静帧预览会明显变样——
这是有意的，预览必须和成片一致。静帧的缓存键因此带上 `placement`：不加的话改了展现方式，
URL 不变，浏览器继续显示旧帧，看起来像「点了没反应」。

顺带一句关于默认值：拖进时间轴的素材块是**静音，也就是 M 亮**。第 115 轮中途试过默认 S，用户
随即更正；第 116 轮用户又把「默认」说得更明确——「M 亮起，即静音」，并且「不允许两者都不亮」。
成片的声音默认是播客，素材的声音永远是用户主动要求的。
### 7.9 模板包与默认模板的五条路（第 138 轮）

模板第一次可以离开这台机器（`docs/video.md` §19.36）。界面上它有五条路，分布在两个状态里
（表里六行：「导入模板包…」两个状态各有一个，动作是同一个）：

| 状态 | 按钮 | 做什么 |
|---|---|---|
| 还没有模板（或上次编译失败） | 导入并编译（主按钮） | 导入本机 PSD 路径 —— 老路 |
| | 用默认模板（ghost） | `POST …/video/template/default`，**不确认** |
| | 导入模板包…（ghost） | 选一个 `.template` 文件 |
| 模板已就绪 | 导出模板包…（ghost） | `GET …/video/template/package` → `saveBlob` |
| | 换回默认模板（ghost） | 同一个端点，**先确认** |
| | 导入模板包…（ghost） | 同上，有模板时**先确认** |

三条不写在代码里就会踩的：

* **「用默认模板」不确认，「换回默认模板」要确认。** 不是措辞不一致：前者发生在空态——那时
  屏幕上没有任何可失去的东西，弹窗只是多一次点击；后者会替换一个用户已经调过九条文字和四个
  头像的模板。确认文案（`templatePackage.ts::REPLACE_WARNING`）明说两件事：「换模板会替换现在的
  文字和头像；原来导入的 PSD 不会被删。」第二句是必须的——不说清楚，用户会因为怕丢 PSD 而不敢按。
* **文件名从 `Content-Disposition` 里读，不在前端拼。** 服务端给的是
  `attachment; filename="template.template"; filename*=UTF-8''<percent-encoded 项目名>.template`。
  `api.ts` 只把**未解析的头**交出来（它刻意不 import 任何本地模块，`api.test.mjs` 在 `node --test`
  下严格解析扩展名），解析在 `templatePackage.ts::filenameFromDisposition`：优先 RFC 5987 的
  `filename*`，`decodeURIComponent` 失败就落回老式 `filename=`，都没有才用兜底名。
  项目名里有中文和空格，`filename=` 那份在某些浏览器上会被截断，所以两条都要留。
* **文件选择器是自己画的 `<input type="file" hidden>`。** 原生选择器的按钮文案不可控（「选择文件」
  与三栏布局的语言不一致），所以 ghost 按钮负责「看起来」，`ref.current?.click()` 负责行为，
  `accept=".template,application/zip"` 负责过滤。上传后不论成败都在 `finally` 里清 `input.value`：
  不清的话选同一个文件第二次不会触发 `change`，用户会以为按钮坏了。

`saveBlob` 从 `App.tsx` 提进了 `download.ts`。原因不是复用，是它里面有一行容易写错又只在真机上
显现的东西：`setTimeout(() => URL.revokeObjectURL(url), 60_000)`。立即 revoke 在大文件上会让下载
中途断掉（Chrome 有时已经在读了，有时还没有）。两个副本里只要有一个漏了这一行，症状就是
「导出模板包没反应」——而被怀疑的永远是后端。

**空态怎么走查。** 界面上没有切换项目的入口（`App` 只认启动时加载的那个项目），所以拿不到一个
真实的无模板项目。`check-r138-template-empty-state.mjs` 用
`Page.addScriptToEvaluateOnNewDocument` 把 `GET /video/template` 的响应截成 `null` 再 reload：
判的是「空态界面长什么样」，不是「后端会不会返回 null」——后者已有单测。

### 7.10 画布编辑器：模板页签里的「编辑布局…」弹窗（第 139→140 轮）

模板的五条路解决的是「换一套模板」，但「这套模板的标题偏右三公分」只能靠改 PSD。画布编辑器把这件
事搬进浏览器（设计在 `docs/video.md` §19.38）。

**它是弹窗，不是页签。** 第 139 轮先做成了第五个页签**布局**，第 140 轮改掉：布局通常一次调完就
不再动，页签等于每期都问一句「这期要改布局吗」。一个页签的代价也不止那一栏——`TabId` 多一个值、
`.video-stage` 多一条 `wants-mid` 判断、预览与 plan 多一个需要 invalidate 的理由。入口现在是模板
页签「框内默认填充」下面的一颗 ghost 按钮，`LayoutDialog` 里只在 `open` 时挂载 `LayoutEditor`，
所以关掉就真的卸载了（`ResizeObserver`、拖拽监听都不留）。

**当初反对弹窗的那条理由被高估了。** 我以为弹窗会挡住预览，但画布里的图层栈**就是**预览的图层栈
——改之前和改之后在同一块画布里对比完，关掉即回到预览。对话框 `width: min(980px, 94vw)`，画布
实测 944 px，比页签里能拿到的 480 px 宽一倍（`check-r139-layout-editor.mjs` 断言 `stageWidth >
600`，就是钉这一条）。

**页脚只有一个「关闭」。** 每次松手都已落库，一个写着「取消」的按钮会暗示「可以全身而退」；
真要回出厂位置，画布下方读数行里的「全部恢复默认」才是那个动作。Escape 与点背景都能关。

**画布是自己画的图层栈，不是 `background.png`。** 底图用 `background_bare_open.png`（无头像的
open 版），再按各自 rect 叠 `plate.png`、`overlay.png`、每个头像的有效 `lit`（换过图用 `edits/`
里的新图）。如果直接铺 `background.png`，底板和头像会被画两遍——它们已经在里面了，再叠一层就是
双影。同一件事在预览里也成立（§19.31.3）。

**缩放手感靠 `ResizeObserver` + `transform: scale()`。** 宿主 `aspect-ratio: 16/9`，stage 用原始
1920×1080 再整体缩放。这样吸附阈值（6 px）、手柄抓取半径（9 px）都是**屏幕**像素，与缩放比例
无关；反过来如果用百分比坐标，用户把面板拉窄之后手柄会变得抓不住。

**一个只在真走查里出现的 bug。** `scale` 的 effect 最初只依赖 `canvas.w`。首帧渲染的是「正在读取
布局…」，`hostRef.current` 还是 `null`，观察器绑不上；而数据回来时画布宽度并没有变（fallback
就是 `template.canvas_w`），effect 不再重跑，`scale` 永远停在初值 0.5。1920 宽的画面在 480 px 的
栏里画成 960 px，右侧被裁掉，**每个框的中心都在可见区域之外**——症状是「拖不动」，实际是
「拖的地方没有框」。修法是把 `state` 也放进依赖：`[canvas.w, state]`。任何「首帧还没有目标节点」
的 `ResizeObserver` 都会重犯这个错。

**手势与提交时机。** 拖动 60 Hz 更新本地草稿，**松手才 `PUT`**；方向键连发时用 400 ms 防抖。
否则一次拖动会打出几十个请求，而每个布局请求都会让文字 PNG 与静帧的缓存键变一次。失败时草稿
回滚成服务端的值——不回滚的话，下一次拖动是从一个服务端不认识的位置开始的。缩放**不**吸附：
移动时吸附到画布中线与其它框的边（参考线真画出来），但缩放的锚点已经是用户挑的那条边了。

**两个「恢复默认」。** 单块走同一个 `PUT`（服务端 `_drop_defaults` 让它等于「没动」），全部走
`POST …/layout/reset`。前者不确认（它只影响一块，而且能再拖回来），后者不确认也会被用户当作
「手滑了」——所以「全部恢复默认」保留在主操作层，不藏进菜单。

**走查怎么判「真的落库了」。** `scripts/check-r139-layout-editor.mjs` 拖完之后 `location.reload()`
再展开面板、再打开一次对话框，断言「已改动」还在、库里的 `changed.texts.title.x` 小于编译值。
只判前端的「已改动」记号是假判据——它可以在完全没写进数据库的情况下亮着。脚本第 0 组判据是
「『布局』页签不存在、按钮存在、点之前没有模态框」，防的是改了一半、两个入口都在的样子。
